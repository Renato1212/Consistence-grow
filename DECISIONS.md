## Phase 8 — Import/Export & backups

- 2026-09-26 — CSV import is a fills importer (spec §7): the browser parses the file, maps columns (presets in `import_presets`, columns guessed from common headers), resolves platform symbols to instruments (explicit map → exact → futures code root + month + year, e.g. ESZ6/ESZ26/MESH27/6EZ6, per token so `ESZ6.CME` works), converts wall-clock timestamps from the file's time zone (DST-correct) and prices (32nds for treasuries). Unknown symbols and bad rows are listed with row numbers and skipped, never guessed.
- 2026-09-26 — Round trips: flat → flat per account and instrument in time order (file order breaks ties); scaling in/out uses weighted-average entry/exit and total contracts (exact P&L); a fill that crosses zero closes the trade and opens the next with the remainder (fees pro-rated); a position still open at the end of the file is reported and not imported. No sample platform CSV was available, so there are no built-in presets — the mapping is set once in the app and saved.
- 2026-09-26 — Idempotency: fill hash = SHA-256 of account, symbol, time, price, qty, side (+ an occurrence number for identical fills in one file); trade `import_hash` = hash of its fills. A trade is skipped when its hash or any of its fills exists (including trades in the trash). The commit is one `import_trades` transaction (RLS, trigger-computed P&L); a fill that appears meanwhile aborts the whole import. Known edge: re-importing an overlapping file whose boundary is a reversal skips the trade that started with the already-imported split fill.
- 2026-09-26 — Imported trades are Taken with `needs_review`; a trigger clears it when a primary domain is set. Today shows "N imported trades need tagging" → Journal filtered to them.
- 2026-09-26 — Export (`/api/export`, signed-in, RLS): zip with one JSON of every user table (soft-deleted rows included; token hashes excluded), a CSV per table and media links signed for 7 days. `fflate` added for the zip.
- 2026-09-26 — Backups: Vercel Cron `0 3 * * 0` → `/api/cron/backup` (Bearer `CRON_SECRET`, service key `SUPABASE_SECRET_KEY`, both server-only env vars) writes `backups/<user>/<date>.json` to a private bucket (owner-only storage policies), keeps the newest 12, then `purge_trash` (service role only) hard-deletes rows soft-deleted more than 30 days ago (instruments excepted) and the route removes their media files. "Back up now" writes the same file as the signed-in user. Without the env vars the route answers 503 and Settings shows "not configured".

## Statements — daily broker statements (Axia)

- 2026-09-29 — Owner's request: ingest the daily Axia "Daily Detail Statement" PDF (Axia Pro Trial, simulated) and use it for analysis and playbooks. Only Axia's format for now (owner's choice). The statement has fills without times, so it never creates journal trades: it is the broker's official record per day and product, stored on its own and reconciled against the journal.
- 2026-09-29 — Parsing on the server (route handler, Node) with `unpdf` (pdf.js, serverless build): positioned text runs → lines (±2pt baseline) → cells; long vs short by the column's right edge; product names split across runs are joined. Everything not understood goes to `unparsed` and a warning, never dropped. `pdf-lib` (dev only) generates anonymised statements with the real layout for unit, DB and E2E tests; the owner's statement never enters git.
- 2026-09-29 — Self-checks before saving: per product printed totals = lines (both sections), purchase & sale amounts = realized P/L (±0.6¢ per line: Axia rounds treasury prices to 5 dp), products = P&S total = summary realized, close cash = open + flows ∓ charges (either sign convention), NLV = today's NLV history, every P&S fill of the day is a confirmation. A failed check stores the statement as "needs attention" (shown everywhere), nothing is corrected. Unflat products / open confirmations are warnings (positions carried).
- 2026-09-29 — Storage: `statements` (summary columns + every printed summary row as JSON, NLV history, checks, extracted text), `statement_products`, `statement_fills`, `statement_code_map`; one active statement per account and trade date; same file (SHA-256) again = no-op; a different file for a stored day needs an explicit Replace (old one to the 30-day trash). PDFs in a private `statements` bucket (owner-only). `save_statement` / `ingest_statement` (token scope `statements`, anon-only) share `private.store_statement`; the token path cannot set a storage path and keeps the text only.
- 2026-09-29 — Product codes: Axia clearing codes seeded in code (21→ZN, MS→MES, EF→MCL, MG→MGC, EC→6E, J1→6J with price scale 0.0001 — the yen is printed per 10,000), then a guess from the description (flagged "guessed"), and the owner's own map wins (`map_statement_code`, applies to past statements too). The contract multiplier implied by the amounts proves each mapping ("size verified" / "size mismatch": MCL vs CL is tenfold). MCL and MGC added to the default instruments (seed function + existing users).
